## 2. 验收步骤(5 组,操作 → 预期 → 判定)

判定取值:**PASS / FAIL / N-A**(N-A 需写明原因,如准备材料不含该场景)。

### HR-1 Save As publication 向导(核心迁移事务)

| # | 操作 | 预期 |
| --- | --- | --- |
| 1.1 | 在 v1 项目中发起 Create Pendulum experiment(入口:File 菜单/任务卡,以 S5 为准) | 出现向导/对话框,提示这将**另存为新的 publication 项目副本**,原项目保持 v1 不动 |
| 1.2 | 选择一个新目录(建议含中文,如 `单摆-公开实验`) | 接受;目录已存在/为源子目录时被拒绝且有明确提示 |
| 1.3 | 完成向导 | 新目录生成并可继续;源 v1 目录**不被锁、可同时用另一次启动打开**(见 HR-4.4) |

### HR-2 四 role 绑定与 legacy 清理

| # | 操作 | 预期 |
| --- | --- | --- |
| 2.1 | 在向导/设置 UI 中为 tip / body_top / body_bottom / pivot 选择或创建四个 track | 每个角色有明确标识;选到不同视频/重复 track 时被拒绝并说明原因 |
| 2.2 | (若材料含旧单轨激活 track)完成绑定后查看该 track | 不再显示旧单轨"Active"状态;历史记录仍在(归档而非删除) |
| 2.3 | 改名任一 bound track 后查看 experiment | role 归属不变(身份只认 UUID,显示名可改) |

### HR-3 setup 事实录入(scale / pivot / vertical / L / g / release)

| # | 操作 | 预期 |
| --- | --- | --- |
| 3.1 | 复用既有标定流程设置 scale | setup checklist 中 scale 项完成;不出现第二套标定入口 |
| 3.2 | 在视频上点选 fixed pivot(单点) | 落点显示为固定 pivot 标记 |
| 3.3 | 点选 true vertical 两端(top→bottom 顺序) | **UI 明确要求先上后下、并解释"向下方向"含义**;确认前状态为"未确认";修改任一端点后回到未确认,需重新确认 |
| 3.4 | 输入 L(米)与 g,并填写来源;设置 release 为当前帧 | 数值非法(0/负/空)被拒;checklist 相应项亮起 |
| 3.5 | 观察 setup checklist/task card | 每一项准确反映"已完成/缺什么",**没有把缺失项显示为完成**(尤其:未设 release 时应提示"可标注、不可分析") |

### HR-4 保存重开、源独立性、撤销

| # | 操作 | 预期 |
| --- | --- | --- |
| 4.1 | Save,关闭,重新打开新目录 | experiment、四 role、几何、L/g、release、checklist 全部一致恢复;无"未保存"误报 |
| 4.2 | 重开后 undo/redo 若干步 | 状态完整往返,无悬空引用报错 |
| 4.3 | 对 setup 事实做一次修改(如改 release 帧)后查看(若有结果展示) | revision/状态按预期更新,提示哪些因此失效 |
| 4.4 | 用第二次启动打开**源 v1 目录** | 正常打开、仍是 v1、原数据完整;对副本的任何操作不影响源 |

### HR-5 guard 与错误可操作性

| # | 操作 | 预期 |
| --- | --- | --- |
| 5.1 | 对 bound track 尝试旧单轨操作(Activate/Replace/Clear/启动训练或推理,入口以 S5 为准——若 UI 已隐藏这些入口则为 N-A) | 被拒绝,消息**指明该 track 绑定了 pendulum 角色、应走 pendulum 工作流**,而不是泛化的"操作失败" |
| 5.2 | 对未绑定 track(若存在)做同上操作 | 行为与旧版一致(不退化) |

## 3. 封闭式问题(逐条回答)

- **Q1** 向导的步骤顺序与文案是否让你清楚知道"在做什么、会产生什么"?A 清楚 B 某步模糊(请注明) C 混乱
- **Q2** true vertical 的 top→bottom"向下方向"提示是否无歧义?A 无歧义 B 有歧义(说明哪里)
- **Q3** setup checklist 是否准确反映缺口、有没有误导?A 准确 B 有误导(请注明)
- **Q4** guard 类错误消息是否能让你知道下一步该做什么?A 能 B 不能(附消息原文)
- **Q5** 整个流程中是否有让你犹豫/困惑超过 10 秒的操作?A 没有 B 有(简述)

## 4. 通过标准

1. **HR-1 … HR-5 全部 PASS**,或 N-A 且理由成立(如材料不含该场景、UI 无该入口);
2. Q1–Q5 无 C 级回答,Q2/Q3/Q4 无"看不懂/被误导"级回答;
3. **数据安全项一票否决**:HR-1.3 / HR-4.1 / HR-4.4 任一 FAIL 直接判不通过——源项目被改动、副本丢数据、重开不一致都属于此类;
4. FAIL 处置:
   - **Blocking**(数据安全、错误结果、无法继续):修复 → 重跑相关自动化 → **只重测受影响的验收项** → 重新判定;
   - **UX/文案类**:由你裁定"必须修"或"记录后延后";裁定延后的 finding 写入 review record 后不影响通过;
5. 通过后动作:Agent 执行 S6 收尾(Independent re-review → `--no-ff` 合并回 publication 集成分支 → 文档同步);用户明确说"跳过本次 HR"时,在 Result 中如实记录后继续(不冒充通过)。
