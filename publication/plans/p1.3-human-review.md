## 2. 验收步骤(操作 → 预期 → PASS/FAIL)

### HR-A 联合训练主流程

| # | 操作 | 预期 |
| --- | --- | --- |
| A1 | 测量卡点 "Freeze fixed-check frames" | 确认框列出预选帧号(基于 10 个 complete 帧的等间隔子集);确认后状态栏 "Fixed-check set frozen: […]" |
| A2 | 测量卡点 "Run joint training" | 状态栏 "Joint training run … started on cpu (external worker…)",卡片/历史出现 pending→running 的 train run |
| A3 | 等待训练完成(几分钟) | 状态栏 "Joint training complete: model … registered as unverified (cpu, Ns)";运行中可见 worker 日志在 data/engines/<run>/worker.log 增长 |
| A4 | 训练中点应用内别处(打开项目/发起单轨 AI) | 被阻断并提示先取消模型任务(不能在训练中换项目) |
| A5 | 再发起一次训练,立即取消 | 状态栏先 "Cancelling…",数秒后 "Model task cancelled";run 状态为 cancelled 而非 failed;experiment 未被锁死(可再次发起) |

### HR-B 教师模型导入

| # | 操作 | 预期 |
| --- | --- | --- |
| B1 | File > Import DLC Model… | 向导打开,提示选 bundle 目录 |
| B2 | 选一个含 config.yaml 的目录 | 显示 bodyparts 列表;四个映射下拉默认**空白**(同名 role 才自动直映);checkpoint 下拉列出 .pt 文件;pose_cfg 检测状态 |
| B3 | 故意留一个 role 不映射,点 Import | 拒绝并提示哪个 role 未映射(fail closed,不静默落到第 0 项) |
| B4 | 补全映射(四 role 各选一个,不重复),Import | 成功:状态栏 "Teacher model … imported (unverified)";若勾选自检 → 自动开始并最终 "compatible" |
| B5 | 导入后把原 bundle 目录移走/改名 | 项目内模型仍可用(availability 不受原目录影响) |

(测试 bundle 可从 A3 的 run 目录构造:复制 config.yaml、snapshot .pt、dlc-models-pytorch/**/train/pytorch_config.yaml 改名 pose_cfg.yaml;或让 agent 准备一份。)

## 3. 封闭式问题

- Q1 训练发起→完成的状态提示是否清楚"在做什么、在哪看进度"?
- Q2 取消行为(提示→取消→状态)是否符合预期?
- Q3 导入向导的映射交互(空白默认/逐 role 选择/错误提示)是否清楚?
- Q4 有无让你犹豫超 10 秒的地方?

## 4. 通过标准

1. HR-A/B/C/D 全 PASS(或 N-A 且理由成立);
2. Q1–Q4 无严重问题;
3. 数据安全一票否决:训练完成但模型引用丢失、导入后文件不齐、undo 破坏 run/model 状态任一出现即不通过;
4. blocking FAIL → 修复后只重测受影响项;UX 类由你裁定;
5. 通过后:P1.3 合并关闭 → P2(adopted measurement / θ 分析)待授权。
