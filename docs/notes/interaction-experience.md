- 触发场景：Phase 5.6 真实闭环执行（建议帧 → 标注 → 训练 → 推理 → 挖掘 → 审核 → 再训练 → 激活）

## 1. 用户报告（原意保留）

> 我尝试训练和推理，**整个交互逻辑非常混乱**。我作为使用过 DLC 的用户使用尚且有些混乱，
> 更别说没有使用过相关 AI 软件的目标用户（researcher、physics teacher）了。
> 交互逻辑要改变：**用户不清楚"我到了这一步，下一步需要做什么"**，也不想知道很多术语，
> 例如多轮的训练集和推理选择。用户只想知道：**这轮之后是否还需要训练？是否可以出图了？**
> 不想去选择训练集或推理集，思考哪个更好。

## 2. 目标用户与他们真正关心的三个问题

| 目标用户 | 背景 | 期望 |
| --- | --- | --- |
| 物理研究者 / 物理教师 | 会做实验、会处理数据、会看图表；**不做 AI 工程** | 拿到可用的轨迹与图表，判断物理结论 |

他们在任何时刻只问三个问题：

1. **我现在在哪一步？**（机器在干活，还是等我操作？）
2. **下一步要我做什么？**（要标几帧？要等？还是可以出图了？）
3. **我什么时候能拿到结果？**（能不能画图/导出）

**现状：这三个问题在界面上都没有直接答案。** 界面呈现的是内部对象（run、series、activation、
mode），而不是用户的这三问。

## 3. 摩擦清单（按用户实际路径，逐项）

UI 位置统一在 `src/ai_physics_tracker/gui/task_panel.py`（"AI tasks" 底部面板，与图表面板同标签页）。

### A. 起始：建议帧与标注

| 现状控件 | 用户看到 | 困惑点 |
| --- | --- | --- |
| `Suggest Frames` + `Frames to suggest` + `Algorithm`(K-means/Uniform) | "算法二选一" | 用户不知道 K-means 与 Uniform 差别，也不知道选几个帧合适；这是**系统该决定的事** |
| 建议帧列表 + 双击跳转 | 帧号清单 | 没有告诉用户"为什么是这些帧"、"要标几帧才算够" |

### B. 训练

| 现状控件 | 困惑点 |
| --- | --- |
| `Mode`：Restart / Resume (fine-tune) | **"从头训练"还是"继续训练"是系统该决定的**；用户无法判断哪个更好（本轮真实闭环中，甚至出现过模型建议与真实最优相反的情况） |
| `Epochs this run`、`Batch size`、`Device` | 对普通用户是无意义参数的组合；默认值本就够用 |
| Advisor 摘要（`resume (epochs=25)` 等） | 动作名是内部枚举（见 §3.G），且要求用户自己判断该不该听 |

### C. 推理

| 现状控件 | 困惑点 |
| --- | --- |
| `Inference model` 列表里选一个 **train run** | 用户被迫在多轮模型之间选择："哪个更好？"——这正是用户明确表示**不想做**的决策 |
| `Minimum confidence` | 概念泄漏（阈值属于引擎细节） |
| 推理完成 ≠ 结果生效 | 用户以为"点了推理就有轨迹了"，实际还要去 history 里找到那个 run 再激活 |

### D. 挖掘与审核

| 现状控件 | 困惑点 |
| --- | --- |
| `Top N`、`Min gap` | 参数暴露；普通用户无从判断 |
| 候选"原因"标签：`screening` / `low_confidence` / `jump_outlier` / `residual_outlier` / `prior_correction_neighborhood` | **纯内部术语**；本轮实测还出现"模型饱和时用 screening 补满队列"导致用户审了 10 个并不困难的帧（已修正为明示"未发现困难帧"） |
| Accept / Skip / Correct / Delete + 快捷键 | 这一组交互相对清楚，但"批次"概念与"审核进度"缺少全局提示 |

### E. 激活（Activate / Replace / Clear）

| 现状 | 困惑点 |
| --- | --- |
| 三个按钮 + `Active AI: xxx` + `Validation: xxx` 标签 + `legacy_inferred/mixed` 状态 | 这是**结果版本管理**（AI 工程概念），不是物理实验概念。用户只想知道"现在的轨迹对不对、能不能画图" |

### F. 固定验证集（Validation Series）

| 现状 | 困惑点 |
| --- | --- |
| `Manage Validation…` 对话框：勾选帧 → `Freeze & Activate Series`；失效提示 | 用户需要理解"为什么要冻结一组帧"（为了公平比较）与"series 为什么会失效"（标注被改动）。术语 `validation series` 与目的之间存在鸿沟；本轮真实闭环中，用户并不清楚它是否还在生效 |

### G. Advisor 动作名直接暴露

界面出现的是规则枚举原文：

```text
Advisor: fix_prerequisite
Advisor: resume (epochs=25, batch=8)
Advisor: label 5 more frame(s)
Advisor: stop_and_compare
```

对研究者而言，这些英文动作名既不是术语也不是指令。用户需要的是**一句话人话结论**（"模型已经够用，可以画图了" / "请再标 5 帧，重点看摆动两端"）。

### H. Task history 与详情

| 现状 | 困惑点 |
| --- | --- |
| 项目级列表混放 train/infer run，标签形如 `train · completed · iter 1 · 9d310620 · snapshot-best-010.pt` | 用户要的是"这一轮模型好不好、能不能用"，看到的是 run id 与文件名 |
| 详情面板堆叠 device / evaluation / 指标 / lineage | 信息完整但**无层次**；关键结论（能否出图）不在其中 |

## 4. 根因分析

1. **内部概念直接暴露**：run / inference run / validation series / active pointer / training mode /
   activation history 都是为了**可追溯的科研记录**而设计的（正确的数据层目标），但被 1:1 投影到了
   面向终端用户的界面上。
2. **逐 Subphase 叠加，未做整体信息架构**：5.1 建议帧 → 5.2 挖掘 → 5.3 审核 → 5.4 激活与验证 →
   5.5 Advisor 与 Resume，全部落在同一个 `TaskPanel` 上，控件按时间顺序堆叠。
3. **"用户显式发起"的硬性不变式被误译为"用户必须理解并选择技术对象"**：不变式的本意是
   "AI 不自动改数据、不自动训练"——它可以由"系统给出唯一推荐 + 用户一次点击"满足，而不必让用户
   在 mode / run / series 之间做选择。
4. **缺少"当前状态 → 下一步"的单一入口**：Advisor 只存在于训练区的一段文字里，且使用内部动作名。

## 5. 改进草案（供讨论，尚未实施）

### 5.1 原则

| 原则 | 含义 |
| --- | --- |
| 单一主流程 | 界面只呈现"当前阶段 + 一个主动作"，其余全部收起 |
| 系统默认、用户确认 | 模型/参数/是否继续由系统**唯一推荐**，用户一次点击即执行（不改变"用户显式发起"不变式） |
| 隐藏决策对象 | train/infer run 列表、验证集、激活指针默认不可见；高级用户可在折叠区操作 |
| 面向结果的语言 | 一切文案回答"能不能出图/还差什么"，不出现内部术语 |
| 术语替换 | Restart/Resume → "从头训练 / 在上次基础上继续"；validation series → "固定检查帧"；Activate → "采用这个结果"；screening/low_confidence/jump → "模型没把握的帧" |

### 5.2 建议界面形态（草案）

```text
┌──────────────────────────────────────────────────────────────┐
│ ① 标注  →  ② 训练  →  ③ 检查  →  ④ 完成（可出图）              │  ← 阶段条
├──────────────────────────────────────────────────────────────┤
│  当前阶段：② 训练                                             │
│  下一步：用最新标注继续训练（约 25 轮，系统已选好参数）          │
│                                                              │
│            [ 继续训练 ]        [ 不用了，直接出图 ]            │  ← 单一主动作
├──────────────────────────────────────────────────────────────┤
│  ▸ 高级设置（参数 / 历史轮次 / 检查帧 / 手动激活）              │  ← 默认收起
└──────────────────────────────────────────────────────────────┘
```

- 阶段由系统判定（如：标注 < 阈值 → 阶段①；训练完未检查 → 阶段③；检查完且指标稳定 → 阶段④）。
- "继续训练/直接出图"两个按钮覆盖用户 90% 的选择；`Resume vs Restart` 由系统按"
  上次训练是否失败/是否恶化"决定并写在说明文字里。
- 完成后提供直达图表的入口（现有 `ChartActions` 面板），不再要求用户理解激活。

### 5.3 与现有不变式的兼容性

- AI 预测不自动成为标签、不自动训练、不自动激活：**全部保留**——系统只做默认选择与建议，
  动作仍由用户点击。
- run / 产物 / lineage 的记录方式**不变**（不改数据模型、不改 schema），因此这是**呈现层重构**。

### 5.4 代价与风险

| 项 | 说明 |
| --- | --- |
| 影响面 | `task_panel.py` 信息架构、`tracking_actions.py` 的呈现逻辑、Advisor 输出语汇、审核/激活/验证集的呈现层；`suggested_frame_review_actions.py` 的状态提示 |
| 域层/持久化 | **不需要改**（ADR-0013/0014/0015 契约保持） |
| 风险 | 过度隐藏会削弱高级用户控制力 → 用"高级"折叠区保留全部能力；阶段判定规则需要明确且可见（可解释） |
| 验证方式 | 必须 Human Review（目标用户视角）：只给用户看阶段条与下一个动作，观察其能否独立完成一次闭环 |

### 5.5 建议实施时机

作为 **Phase 6 之前的独立交互重构 Subphase**（如 5.7 或 6.0），单独出 mini-plan；本轮仅记录，
不改动现有交互。

## 6. 与本轮技术发现的关联

- **F1/F4（模型饱和时挖掘无"困难帧"）**：典型的"让用户做无意义决策"。系统应直接说
  "当前模型在整段视频上都稳定，无需再审"，而不是给 10 个凑数候选。
- **F5（基准被反复使用）**：`validation series` 对普通用户没有意义，应改为后台管理的
  "固定检查帧"，只在需要比较时以一句话呈现（"与上次相比：略好 / 基本持平"）。
- **AC-9 的教训**：把"是否改善"的判断交给用户（读 RMSE 趋势）不现实；应由系统给出
  "够用了 / 还需要补标注"的结论并附一句人话证据。
