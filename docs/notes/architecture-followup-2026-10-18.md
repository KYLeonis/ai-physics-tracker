## 第一批建议：计算设置只解释一次

### 已核对的具体重复

- `application/chart_recipe.py:46`与`application/kinematics_job.py:175`分别定义kind与导数阶的对应关系；`signal_analysis_job.py:276`又以条件表达式定义一次。
- `signal_analysis_job._recorded_source_settings`和`gui.chart_actions._seedControlsFromDerived`都将记录中的角参考重建为PendulumReference / TwoPointReference。
- `ChartPlot._legendName`通过`pipeline_summary.split`及英文`Savitzky-Golay`判断来源；改展示文案可能影响图例含义。
- `run_kinematics_job`仍覆盖同步计算已经写入的timing_context；重复写入不等于当前数值出错，但增加需要同步维护的位置。
- 本轮已关闭的F1–F3揭示了轨迹归属、单条合法性、组内一致性是三种不同检查；不能以一个简单valid标记混合。

### 建议范围与完成判据

1. 将已知源记录的类型、角参考、SG参数、时序与单位含义集中解释；写入 / 校验 / 设置恢复共用同样的事实。让现有module获得depth，而非叠加一层转发。
2. 图表直接消费来源事实，删除通过展示文字反推计算含义的逻辑。GUI作为adapter，只显示事实。
3. 共享事实跨越同一seam，但保留“可显示旧缓存”“可作当前计算输入”“可自动重算覆盖”的不同策略；不删除科学输入 / 目标版本核对。
4. 保留JSON、未知字段 / 未知步骤原文、记录扩展、同步入口、后台原子批次和Undo语义。验证相同输入的数值 / 配方及拒绝条件保持一致，时间戳 / UUID等身份字段不要求逐字相同。

技术收益：interface让调用方少知道配方细节，locality使同一规则在一个位置维护，leverage由图表 / 拟合 / 后台等实际调用方复用。deletion test要求旧判断和手工重建确实消失；不是仅把它们包在新函数后。此处尚未冻结interface或新module名称。

风险分级：High-risk（科学配方解释 / 校验）；实施前mini-plan / Review Gate，既有ADR-0019 / 0020 / 0021 / 0023 / 0025不变。不引入依赖或文件格式迁移，不将重复间隔自动重算偷偷混入这次内部整理。

## 后续次序

1. 上述整理后，重复间隔工具可复用同样的源准备与解释；是否自动准备源、是否自动找交叉事件、是否正式发布结果应分别决定，不能把“联动”理解成自动改写所有结果。
2. 计算与结果装配分离：同步与后台共用无活动Session写入的计算implementation，Session仍负责发布 / stale / Undo。若仍需传整个Session和多组回调，则没有获得更好的seam，应重划范围。
3. 更广任务生命周期、Undo、渲染统一，仅在具体新功能证明重复时再立项。
