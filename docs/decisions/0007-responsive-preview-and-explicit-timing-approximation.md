# ADR 0007: 首帧预览与显式近似时序

## Status

Accepted (2026-08-30，用户授权执行 Human Review 反馈修复)

部分取代 ADR-0006 Decision 1/4/5 的加载时机与时序门禁；其他条款不变。

## Context

P001.mp4 的首帧约 0.14 s，完整帧解码探测约 91.91 s。完整 packet PTS 扫描
约 0.26 s，排序后与该文件的完整帧 PTS 一致。其帧间隔并非严格恒定，但相对
容器平均 FPS 网格的全片最大偏差仅 0.17014 ms。不能把这类媒体静默标为 CFR。

## Decision

1. 新视频首帧成功即提交只读预览；时序探测与 SHA-256 在后台继续。播放、跳帧、
   缩放不等待验证。身份校验失败的重连仍不得替换原项目；已有项目的身份检查保持候选式。
   后台结果携带固定加载代际，不能覆盖后来打开的视频；退出/替换可以取消后台验证。
2. FFprobe 对 MP4/MOV 中适用的 H.264/HEVC 使用完整 packet PTS 快路径：必须有完整
   PTS、合法包信息、声明帧数与实际包数一致；按呈现时间排序处理 B 帧。不满足条件时
   回退完整帧探测；错误、缺工具、取消或超时保持 unknown。该路径检查时间索引，
   不宣称已经逐帧验证像素解码完整性。依据：[FFprobe 文档](https://ffmpeg.org/ffprobe.html)。
3. 保留严格 CFR 分类；新增独立 `near_cfr` 结论。仅在全片时间戳严格递增、相对
   明确 FPS 的每帧累计误差和单帧间隔误差均不超过 `min(1 ms, 帧周期的 1%)` 时，
   提供近似测量选择。这是产品的保守选择上限，不是通用实验精度保证。
4. UI 常驻显示验证状态；near_cfr 必须展示当前 Timeline FPS、全片最大时间网格偏差
   和间隔偏差。用户明确接受后才启用 Add track/落点；拒绝仍可浏览，允许稍后确认。
   unknown/超预算的 VFR 没有绕过按钮。保存的 Timeline 不自动更改，若其 FPS 与探测
   参考不同，必须重新保守计算该时间网格的误差上界，超预算不允许近似。
5. 近似授权仅在本次文件会话有效，保存/重开必须重新验证确认。近似标记在既有
   TrackPoint.source_detail 中记录方法、FPS 和误差上界，以免科学数据失去来源说明。
   不变更 schema，不改写原视频，不改写已有观测时间，不把近似标为精确 CFR。

## Consequences

- 普通文件迅速进入预览；慢格式仍可能后台全解码，但不遮住视频。
- 引入一个显式确认交互；要求高于该误差界限的实验应另用可靠 CFR 来源。
- 时间网格偏差不等于速度/加速度误差保证，未来物理分析必须保留这一限制。
- 自动化验证包含慢 probe、取消/切换、近似确认、raw 来源保留；仍由用户 Human Review 验收。
