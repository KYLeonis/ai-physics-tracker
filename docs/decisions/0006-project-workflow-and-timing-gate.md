# ADR 0006: 项目工作流采用候选提交与 FFprobe 时序关卡

## Status

Partially superseded by ADR-0007 (2026-08-30；Decision 1/4/5，其余保持 Accepted)

## Context

现有桌面标注会话尚不能首存、加载和重连；打开媒体前清空旧项目会导致未保存标记丢失。
OpenCV 提供的平均 FPS 不能证明 CFR；ADR-0005 已要求 unknown 不得直接进入测量。

## Decision

1. 清单、视频和首帧先在候选会话准备，成功且未取消后才替换活动 ProjectSession。
   保存副本成功后才更改根目录；内容 dirty 与最后保存快照比较，不由播放/缩放驱动。
2. 首存保留 Project ID 与完整对象图。另存拒绝已有目录、同目录及源目录子目录；使用
   目标父目录内的暂存单元，失败保留带明确路径的可恢复暂存内容，不自动删除用户文件。
3. 多视频项目只允许一个活动视频。恢复使用清单中的 Timeline；UI 上下文在既有
   `ui_state.workflow` 命名空间兼容追加，保留未知键，schema_version 不变。
4. FFprobe 作为可定位的外部只读探测工具；由组合根注入应用层端口，不取代 OpenCV。
   检查完整逐帧时间信息，不把少量抽样或平均 FPS 相等视为 CFR 的充分证据。
   工具缺失、取消、超时、缺失时间戳或无法确认均为 unknown；不自动转码。
5. 新增测量要求当前文件验证为 CFR。已有 unknown/VFR 项目仍可打开、保存和重连，
   但不允许新增点；已有 raw 时间/坐标绝不重写。验证结论不作为跨文件可复用的永久标志。
6. 开发时发现 PATH 中 FFprobe，或由用户选择可执行文件；不安装全局依赖、不改系统 PATH。
   CI 中取得工具并运行真实探测器测试，版本/来源记录在 workflow；不靠 mock 完成验收。
7. GUI 改动在自动化验证后必须 Human Review，用户通过前不合并；Windows 真机是
   Phase 2 收尾关卡，offscreen CI 不替代真人交互。

## Consequences

- 失败操作不污染活动项目，外部媒体仍按 ADR-0004 只引用。
- 完整时间戳扫描可能耗时，因此后台可取消；工具不可用时退化为只读浏览而不是猜测。
- 候选加载期间可能同时持有两个 reader；成功交接/取消必须关闭对应实例，回调带固定代际。
- FFprobe 二进制的最终安装包分发与许可清单仍属 Phase 9，不在本次发布。
