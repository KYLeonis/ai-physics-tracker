# ADR-0023 — 草稿预览与正式计算的执行隔离

## Status

Accepted，2026-10-16，P6.3.1独立复审发现阻塞后作实现调整；仅替代ADR-0022中“预览使用既有单executor”的调度条款，其余契约保持。

## Context

正在执行的Future不能由`cancel()`强制终止。若自动预览与显式Fit排在同一单线程队列，失效预览虽不会发布，却仍能阻塞正式请求。即时反馈应说明真实计算状态，也需要避免自动任务占住用户显式计算路径。

## Decision

SignalPreview拥有独立的单线程executor和取消Event；继续由GUI线程轮询Future，不从worker发射携带Python对象的Qt信号。正式线性/角量/拟合/交叉计算仍共用原来的单executor。连续编辑取消排队预览，只保留最新一项；运行中的NumPy操作不能强行终止，完成后由generation/配方/源指纹拒绝旧值。

关闭窗口时两者分别发取消、取消排队项并shutdown；worker只持不可变快照，不接触Qt或活动工程。预览不发布DerivedData、不记正式尝试，不绕过时序门或保护的参数。无新增依赖，无计算目标或验收范围变化。

## Consequences

最坏同时有一个旧预览和一个正式数值任务，内存开销增加一份预览快照；正式任务无需等待预览队列。取消是协作与结果丢弃，不承诺中断正在执行的单次原生数值调用。
